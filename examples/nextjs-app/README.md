# Example: Next.js + Zod

A Next.js app whose environment contract is kept honest by `env-contract`.

- [`src/env.ts`](src/env.ts) — the Zod schema (server vars + `NEXT_PUBLIC_*` client vars).
- [`src/config.ts`](src/config.ts) — reads `process.env.*`; `scan` cross-checks these.
- [`env-contract.config.ts`](env-contract.config.ts) — ignores `NODE_ENV` and `SKIP_ENV_VALIDATION`.
- [`.env.example`](.env.example) — generated by `env-contract sync`.

## Try it

```bash
npm install
npm run env:check
npm run env:sync
```

## Using `@t3-oss/env-nextjs`?

env-contract treats your validator as the source of truth, so the t3-env setup
works the same way — just point it at your `createEnv(...)` file. See the
**T3 / `@t3-oss/env-core`** and **Next.js** recipes in
[`docs/recipes.md`](../../packages/env-contract/docs/recipes.md), including the
`SKIP_ENV_VALIDATION` pattern for clean CI runs.
